# 如何训练你自己的 LLM 及成功所需的 4 个关键考量

*来源: [Lamatic Labs](https://labs.lamatic.ai/p/how-to-train-your-own-llm/)*

---

## 为什么要训练你自己的 LLM？

### 定制化：根据你的需求定制 LLM

预训练 LLM 用途广泛，但旨在满足各种应用。训练你自己的 LLM 使你能够根据需求定制模型。无论你从事医疗、金融、法律还是任何其他行业，都可以通过微调定制 LLM 来：

- 理解领域特定术语
- 理解上下文
- 理解细微差别

这种级别的个性化可以大幅提高模型输出的准确性和相关性。

**示例:** 医疗机构可以在医学文献上训练定制 LLM，创建能够解释患者症状并生成准确诊断见解的模型。

### 控制：成为 AI 架构师

当你训练自己的 LLM 时，你就掌握了 AI 架构和开发的主动权。完全依赖第三方 LLM 提供商会让你受制于他们的更新、限制和数据隐私问题。

**示例:** 金融组织可以微调 LLM 以预测市场动向、分析监管变化并生成有洞察力的报告。

### 成本效率：优化资源

训练你自己的 LLM 允许你根据需求优化其规模和复杂性。通过制作更精简的模型来交付目标结果，可以节省计算资源和成本。

**示例:** 初创公司可以为虚拟助手训练定制 LLM，使其能够处理相关业务任务，同时减少计算开销。

### 领域专业知识：解决特定挑战

训练你自己的 LLM 让你能够直接解决特定于行业的挑战。

**示例:**
- **医学研究:** 在医学文献中训练的 LLM 可以提供通用 LLM 可能忽略的见解。
- **法律:** 定制 LLM 可以用精确的语言和对法律术语的理解生成法律文件。
- **软件开发:** 根据首选编程语言和实践定制专门的代码生成。

### 伦理 AI：减轻偏见和隐私问题

开发你自己的 LLM 让你能够从一开始就确保 AI 伦理实践。你可以整理无偏见且代表你应用领域的数据集。

**示例:** 用于招聘平台的 LLM 可以分析技能并提供见解，而不会延续偏见。

### 创新与差异化：树立新标准

训练你自己的 LLM 让你脱颖而出，成为创新者。定制 LLM 可以带来新颖的应用程序和改进的用户体验。

**示例:** 媒体公司可以为内容创作训练定制 LLM，以生成符合其品牌声音和风格的的文章、故事和剧本。

## 逐步指南：如何训练你自己的 LLM

### 第 1 步：定义目标 — 明确你的 AI 目的

在开始训练大型语言模型之前，确定模型的目的：

- 你是在创建对话聊天机器人、内容生成器还是针对特定行业的专业 AI？
- 你希望你的 LLM 擅长哪些具体用例？
- 考虑你所选领域的独特挑战和要求。

这第一步完全是关于愿景和目的 — 了解你希望 LLM 实现什么、最终用户是谁以及它要解决的问题。

---

### 第 2 步：收集和准备数据

数据是任何 LLM 的核心。要收集正确的数据：

**识别内部数据源:**
- 电子邮件
- 规划/预测文件
- 项目/产品/技术文档
- 政策/人力资源文档
- 参考文档
- 预算跟踪

**确保多样性:**
- 各种主题
- 各种写作风格
- 各种语境

**创建数据管道:**
- 转换、清理和标准化所有数据
- 将文档标记在相关项目名称下
- 根据项目阶段分类（规划、设计、实施等）

**数据清理:**
- 丢弃过时的文档
- 使用数据版本控制工具管理数据集
- 注意版权和许可问题

---

### 第 3 步：分词（Tokenization）

在分词过程中，预处理后的数据集被转换为词元（token）词汇表：

- 字符
- 单词
- 单词的一部分
- 标点符号
- 短语
- 正则表达式
- 特殊字符

**处理技术:**
- 移除停用词
- 词干提取（移除常见前缀或后缀）
- 词形还原（找到词根）

**工具:**
- NLTK 和 spaCy（Python 自然语言处理库）
- TikToken（OpenAI 的 GPT 模型分词器）

---

### 第 4 步：构建模型架构

模型架构是 LLM 应用的大脑。我们使用 Transformer 模型作为基础。

**Transformer 配置:**
- 仅编码器（如 BERT 系列）— 适合理解任务
- 仅解码器（如 GPT 系列）— 适合生成任务
- 编码器-解码器（如 T5）— 适合序列到序列任务

**嵌入层:**
将 token 转换为数值表示。这很关键，因为 LLM 会对这些嵌入值进行数学计算以学习语言模式。

**在哪里找到嵌入模型:**
- Hugging Face MTEB 排行榜
- Nvidia 的 NV-Embed-v1（目前领先）

**提示模板:**
定义提示模板（如使用 LangChain）来指导 LLM 了解期望什么样的输入提示以及如何响应。

---

### 第 5 步：使用外部向量数据库

向量数据库存储向量嵌入 — token 的高维数值表示。

**流行的向量数据库:**
- pgvector
- Pinecone
- MongoDB Atlas
- Qdrant

**用途:**
对 LLM 中的检索增强生成（RAG）至关重要。它们使 LLM 能够快速访问特定领域的真实数据，从而产生更准确、更符合上下文的结果。

**RAG 管道:**
创建包含你整个知识库的 RAG 管道。你的定制 LLM 可以查询 RAG 存储以获取高度准确的答案。

---

### 第 6 步：实施护栏（Guardrails）

模型训练完成后，考虑其局限性，特别是偏见和幻觉。

**保护措施:**
- 在向用户显示之前监控 LLM 的反应
- 为用户与 LLM 的交互设置自定义 AI 策略和指南
- 创建受限主题列表以避免回答无关问题
- 防止数据泄露（例如，员工薪资包、客户合同）

**工具:**
- Aporia Guardrails — 减轻 RAG 幻觉和提示注入攻击

---

### 第 7 步：评估和微调模型

训练后的模型必须经过评估以确保高质量性能。

**评估指标:**
- ROUGE（用于问答任务）
- MRR（平均倒数排名）
- 尝试多种评估方案以找到最佳匹配

**流程:**
1. 彻底测试你的训练模型
2. 根据你选择的方案进行评估
3. 如果未达到预期结果，要么重新训练，要么微调

---

### 第 8 步：微调（可选）

预训练语言模型在大型且多样化的网络规模数据上进行训练，能够执行广泛的语言任务。

**预训练模型的好处:**
- **更快的训练:** 不需要广泛的微调周期
- **减少的数据需求:** 微调数据集仅包含下游任务信息
- **更好的性能:** 高效适应大多数下游任务
- **知识蒸馏:** 训练模仿大型模型的小型模型
- **迁移学习:** 将学习到的信息转移到其他 AI 模型
- **更快的部署:** 大幅缩短训练时间

**微调流程:**
1. 整理文档并准备微调数据集
2. 对数据进行分词
3. 选择合适的预训练模型（考虑与问题的相似性）
4. 在你的整理数据集上微调模型
5. 尝试不同的超参数配置
6. 使用评估指标分析性能

**用于微调的热门预训练模型:**
- 开源: Llama-3、Mistral
- 专有: GPT-3.5（通过 OpenAI API）

---

### 第 9 步：测试和部署

**测试:**
- 用 AI 将遇到的真实数据测试
- 确保其满足准确性、响应时间和资源消耗要求
- 识别需要解决的任何问题或 quirks

**部署:**
- 集成到网站、应用程序或系统中
- 部署在云服务上或使用容器化平台
- 实现用户身份验证和访问控制
- 使用适当的安全措施处理敏感数据

---

### 第 10 步：持续改进

AI 之旅不会随着部署而结束 — 这是一个持续改进和完善的过程。

**评估方法:**

**内在方法**（定量指标）:
- **语言流利度:** 评估语法正确性和句法多样性
- **连贯性:** 衡量句子和段落间的主题一致性
- **困惑度:** 统计模型预测下一个词的效果（越低越好）
- **BLEU 分数:** 评估机器输出与人类输出的对应程度

**外在方法**（真实世界任务表现）:
- 问题解决能力
- 推理能力
- 数学能力
- 标准化考试（GRE、LSAT、美国统一律师资格考试）

**其他方法:**
- 问卷调查（将 LLM 表现与人类表现比较）
- 常识推理
- 跨领域的多任务准确性
- 事实性测试（准确性和幻觉程度）

## 训练 LLM 的 4 个关键考量

### 考量 1：基础设施 — 了解计算需求

训练 LLM 需要巨大的计算资源:
- LLM 在巨大的文本语料库上训练（至少 1000 GB）
- 模型有数十亿参数
- 在单 GPU 上训练不可行 — 需要数年时间

**示例:**
- 在一个 NVIDIA V100 GPU 上训练 GPT-3（1750 亿参数）需要 288 年
- Google 的 PaLM 模型（5400 亿参数）在 6144 个 TPU v4 芯片上训练

---

### 考量 2：成本 — 了解财务影响

训练 LLM 所需的基础设施可能极其昂贵。

**历史背景:**
- 2019 年，微软向 OpenAI 投资 10 亿美元
- 其中大部分用于在 Azure 云资源上训练 LLM
- OpenAI 没有在自己的基础设施上训练模型

---

### 考量 3：模型分布策略 — 规划高效训练流程

LLM 训练涉及计算资源的复杂考虑。

**模型并行:**
- 在众多 GPU 上分布模型
- 最佳分区增强内存和 I/O 带宽

**张量模型并行:**
- 将模型的各个层分布在多个 GPU 上
- 需要精确编码、配置和仔细实施以实现准确高效的执行

---

### 考量 4：模型架构选择的影响 — 架构如何影响训练复杂性

**适应架构的指南:**
- 平衡可用的计算资源和复杂性
- 使用具有残差连接的架构以简化优化
- 确定是否需要带自注意力的 Transformer 架构
- 识别功能需求（生成式建模、双向/掩码语言建模、多任务学习、多模态分析）
- 使用熟悉的模型（GPT、BERT、XLNet）进行训练运行以了解其适用性
- 确定分词技术（基于词、子词或基于字符）
